# 设计说明与校准依据

## 1. 为什么段落级 + 不做词级删除

- TopicGPT 靠 LLM 语义理解段落，主题由"语义聚类/命名"产生，**不是词频**。删词级停用词对 LLM 无益、反损信息。
- 词级停用词仅服务 **BERTopic 的 c-TF-IDF**（聚类后的表征词提取），与 TopicGPT 主流程正交。

## 2. 预处理校准证据（2026-09-30，274 篇/14,014 段政策标准语料）

| 规则 | 阈值 | 依据 |
|---|---|---|
| TOC | `第[X章/节/编/篇]` 计数 ≥3，或 ≥2 且含"目录" | **排除"条"**：法条正文全是"第X条"，若含"条"会误杀。法律沿革段内嵌目录命中属正确丢弃。命中 ~81 段。 |
| too_short | `len < 12` | 原设 20 误删"电子文件应当实行备份制度"(16 字)等**实质性短条款**；12 只丢标题/碎片。 |
| few_cjk | 中文 < 5 | 命中多为 XML/METS 碎片、标准号、页码标记、电话。抽样 2,350 段确认无误删。 |
| 页码/页眉 | 分页标记 / 孤立页码 / 标准号+页码行（去前缀后中文<6） | 防"标准号开头的正文行"被误判（页眉前缀 `DA/T 47—2009 前 言 …` 中文>6 须保留）。 |

净结果：14,014 → **10,977 保留**（toc 81 / boiler 5 / few_cjk 2350 / too_short 586 / 其他 30）。

## 3. 框架映射的定位（写论文时别混）

- **TopicGPT 内部**：主题树（L1/L2）是对**语料自身**的上位归纳（topic-on-topic），属方法内。
- **框架映射**（map.py）：把主题树挂到 OAIS/治理模型，属**方法外的分析层**，是论文论点所需。
- 两篇切片口径可不同：**小论文**不限领域、落点供给结构差异；**博论**限领域、落点治理模型。语料固定后，映射换表即可复用同一主题树。

## 4. DeepSeek API key 获取（真跑前）

1. 浏览器打开 `https://platform.deepseek.com/`，手机短信/微信登录注册。
2. 左侧「API keys」→「Create new API key」→ 填名称 → 创建 → **立即复制**（`sk-…`，只显示一次）。
3. 「充值」充少量金额（按 token 计费）。
4. `export DEEPSEEK_API_KEY=sk-…`（只放环境变量）。
5. `config.json`：`model=deepseek-v4-flash`，`base_url=https://api.deepseek.com`。

## 5. 运行环境

- Python 3.10+，依赖 `openai`（`pip install openai`）。离线自检不依赖网络。
- 运行前 `cd scripts`（脚本从自身目录读 config.json 与 prompts）；`config.json` 由 `config.example.json` 复制后改 `paths.*`。
- 先 `python self_check.py` 离线自检；再小样本（`--limit 30`）真实跑 → 审阅 → 全量。
